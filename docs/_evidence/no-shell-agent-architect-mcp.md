# No-Shell Agent Architect MCP Evidence

## 1. Customer Dossier

The target user already knows ChatGPT, Claude, Codex, Gemini, Cursor, or Hermes can automate work, but does not know what tool stack, plugin, MCP, skill, command, or validation route to use. The buyer is not looking for one more generic prompt; they need a safe operating route from "automate this" to a sample result that actually works.

Primary buyer segments:
- Solo operators and non-developers who need email, documents, reports, browser tasks, and knowledge-base workflows automated.
- AI automation freelancers who need a repeatable intake, stack route, prompt, and QA pack for client work.
- Agent builders who need a router MCP that recommends practical plugin/MCP/skill combinations before executing work.

## 2. Competitor Teardown

MCP directories such as the official MCP Registry, Glama, Smithery, and PulseMCP make discovery easier, but they do not decide which stack a non-developer should use for one real workflow. They are catalogs. This MCP is a routing and validation layer that consumes catalogs and operating rules.

Sources:
- https://modelcontextprotocol.io/registry/remote-servers
- https://glama.ai/
- https://smithery.ai/
- https://www.pulsemcp.com/

Automation platforms such as n8n and Zapier provide workflow builders and many templates. The gap remains before the workflow builder: the user still has to describe the job, choose tools, define safe boundaries, and know whether the result actually works.

Sources:
- https://n8n.io/workflows/categories/ai/
- https://zapier.com/templates
- https://zapier.com/agents

## 3. Willingness-To-Pay Evidence

This is still a market hypothesis, not proven revenue. The evidence is category-level: people already pay for automation platforms, templates, and agent tooling, but many fail at the "what should I ask and what tools should I use" layer. The first paid route should be low-friction:
- free MCP/API preview
- $29 starter operating pack
- $99 multi-workflow bundle
- $300 custom workflow audit

The MCP itself supports the top of funnel by creating a concrete plan, prompt, and QA pack.

## 4. Category-#1 Thesis

Be the best "no-shell automation architect" for non-developers and solo operators: not a directory, not a prompt pack, not a full automation platform, but the router that turns a vague workflow into stack, prompt, validation, and human boundary.

## 5. GTM

Channels:
- GitHub open-source repository and MCP directories for agent builders.
- Glama/Smithery/PulseMCP/official registry listing for discovery.
- Free diagnostic card and web demo for non-developers.
- Short demonstrations: before "automate this" vs after "tool route + dry-run + QA + boundary".

First hook:
"AI keeps building files that look finished but do not run the real workflow. This MCP tells the agent what stack to use, what command to run, and how to prove it worked."

## 6. Price Ladder

1. Free: remote MCP/API preview and diagnostic card.
2. Starter: $29 one workflow operating pack.
3. Bundle: $99 five workflow packs.
4. Custom audit: $300 one client workflow turned into a tested automation design.
5. Enterprise/agency: custom internal router catalog if real usage appears.

## 7. Kill Criteria

- 20 users try the architect and fewer than 3 say it made their first automation command clearer.
- Agent builders say the output is just obvious prompt advice and not useful as an MCP.
- The tool cannot produce better plans than a good static checklist.
- Users still need direct consulting to interpret every output.

## Strongest Counterargument

This can become another wrapper around generic advice. It survives only if the output is concrete: selected tools, install/connect notes, copy-paste command, dry-run, QA/audit, and recovery path. The validation scripts must keep it from becoming prose-only.
