# Starter Pack — Email & Document Automation

## 한 줄 결론
고객 이메일, 내부 요청, 회의 메모, PDF/문서 내용을 받아서 답장 초안·요약·보고서·체크리스트로 바꾸는 첫 자동화 운영팩이다.

## 고객 상황
고객은 코딩을 배우고 싶은 것이 아니다. 매일 쌓이는 이메일과 문서를 AI가 먼저 읽고 정리하고 초안을 만들며, 사람은 권한 연결·발송·공개·민감정보 경계에서만 확인하고 싶다.

## 자동화 문장
`나는 [허용된 이메일 라벨/검색어/문서 입력]을 받아서 [분류/요약/답장/보고서]로 바꾼 뒤 [Gmail draft/Docs/Sheets/Notion/로컬 파일]에 남기고 싶다. 사람은 [권한 연결/발송/공개/결제/민감정보]에서만 확인한다.`

## 1단계: 업무 좁히기
```text
내 이메일/문서 업무를 자동화 가능한 하나의 흐름으로 좁혀라.
다음 표를 먼저 채워라: 입력, 반복주기, 판단 기준, 결과물, 저장 위치, 사람이 확인할 경계, 실패하면 큰 문제인 부분.
표를 채우기 전에는 코드나 도구를 추천하지 마라.
```

## 2단계: 도구 선택
```text
이 업무에 필요한 도구를 골라라.
도구 없이 AI 대화만으로 가능한 부분, 파일 읽기/쓰기 도구가 필요한 부분, Gmail/Drive/Notion/Sheets 같은 플러그인이 필요한 부분, 권한형 계정 연결이 필요한 부분을 나눠라.
각 도구는 "무엇을 해주는지"와 "왜 필요한지"를 쉬운 말로 설명해라.
```

## 2.5단계: 권한형 계정 자동화 기준
```text
Gmail/Drive/Notion/Sheets 같은 계정이 필요한 경우 우회하지 말고 권한형 자동화 구조를 먼저 설계해라.
다음 항목을 표로 적어라: 연결 방식(OAuth/플러그인/로그인 세션), 허용 라벨·검색어·문서·대상, 자동 실행할 작업(읽기/분류/요약/초안/저장), 초안으로만 멈출 작업, 정확한 지시가 있을 때만 라이브 실행할 작업, 감사로그 위치.
비밀번호, 쿠키, 복구코드, 2FA 우회, 무제한 메일함 읽기는 요구하지 마라.
```

## 3단계: 첫 테스트 입력 3개
```text
실제 자동화를 만들기 전에 테스트 입력 3개를 만들어라.
1개는 정상 요청, 1개는 정보가 부족한 요청, 1개는 민감하거나 사람이 확인해야 하는 요청으로 만들어라.
각 입력에 대해 예상 결과와 사람 확인 필요 여부를 표로 보여라.
```

## 4단계: 결과물 형식
| 입력 유형 | AI가 할 일 | 결과물 | 사람이 볼 경계 |
|---|---|---|---|
| 고객 문의 이메일 | 요청 종류 분류 + 답장 초안 | 답장 초안 | 발송 전 확인 |
| 회의 메모 | 결정/할일/리스크 추출 | 보고서 초안 | 배포 전 확인 |
| PDF/문서 | 요약 + 체크리스트 | 요약문/체크리스트 | 사실 확인 필요 |
| 민감정보 포함 | 처리 중지 + 경계 표시 | 확인 요청 | 사람 직접 처리 |
| 허용된 Gmail 라벨 | 읽기 + 분류 + 답장 초안 생성 | Gmail draft + 감사로그 | 라이브 발송 전 정확한 지시 |

## 5단계: 빈껍데기 방지 검증
```text
지금 만든 이메일/문서 자동화 흐름을 검증해라.
테스트 입력 3개에 대해 예상 결과와 실제 결과를 비교하고, 실패한 항목은 게이트를 추가하지 말고 원인을 고쳐라.
원인 후보는 목표 불명확, 입력 누락, 도구 미연결, 권한 부족, 출력 위치 없음, 사람 경계 누락 중에서 고른다.
```

## 납품 기준
- 사용자가 복사해서 AI에 붙여넣을 명령어가 있다.
- 테스트 입력 3개가 있다.
- 예상 결과와 실제 결과 비교표가 있다.
- 권한형 계정 연결, 초안/라이브 실행, 사람이 확인해야 할 경계가 분리되어 있다.
- 실패했을 때 원인을 고치는 문장이 있다.
