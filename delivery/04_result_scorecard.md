# 04 Result Scorecard

각 항목을 0/1/2점으로 본다. 16점 이상이면 판매 가능한 결과, 12-15점은 보강 필요, 11점 이하는 껍데기다.

| 항목 | 질문 |
|---|---|
| 목표 | 사용자가 얻는 실제 결과가 한 문장으로 보이는가? |
| 입력 | 자동화가 받을 자료와 위치가 명확한가? |
| 처리 | AI/도구가 무엇을 판단하고 무엇을 하지 않는지 명확한가? |
| 출력 | 결과물이 어디에 어떤 형식으로 남는가? |
| 권한형 계정 자동화 | OAuth/플러그인/로그인 세션, 허용 라벨·검색어·URL·대상, 초안/라이브 실행이 분리됐는가? |
| 사람 경계 | 발송/결제/공개/비밀/계정 변경 같은 정확한 라이브 실행 순간이 분리됐는가? |
| 실패복구 | 실패했을 때 원인 후보와 다음 행동이 있는가? |
| 검증 | 테스트 입력과 예상 결과가 있는가? |
| 자연어 | 비전공자가 읽고 행동할 수 있는가? |
| 재사용 | 다음 업무에도 구조를 다시 쓸 수 있는가? |
| 기록 | 나중에 이어받을 로그/메모 위치가 있는가? |

## 즉시 FAIL
- 버튼이나 페이지는 있는데 실제 입력/출력 흐름이 없다.
- "AI가 알아서"라는 말로 검증을 건너뛴다.
- 계정/결제/공개발행/비밀키 경계를 숨기거나 로그인/2FA/쿠키/토큰 우회를 요구한다.
- 메일함/커뮤니티/브라우저 자동화를 만들면서 허용 범위, 초안/라이브 분리, 감사로그가 없다.
- 실패하면 멈추기만 하고 원인을 고치지 않는다.
