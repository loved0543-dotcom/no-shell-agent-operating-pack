# 05 Recovery Playbook

## 문제: 결과물이 껍데기다
원인 후보: 목표가 흐림, 입력/출력이 없음, 도구가 실제로 연결되지 않음.  
복구: 목표 문장을 `입력 -> 처리 -> 출력 -> 사람 경계`로 다시 쓴다.

## 문제: AI가 자꾸 장황하게 말한다
원인 후보: 결과 형식과 길이 제한이 없음.  
복구: "최종 답은 10줄 이내, 긴 근거는 파일/노트에 저장"을 명령에 넣는다.

## 문제: 플러그인을 많이 추천하지만 실행이 안 된다
원인 후보: 도구 선택 전에 업무 단위를 좁히지 않았다.  
복구: 도구를 고르기 전에 첫 10분 테스트 흐름을 먼저 만든다.

## 문제: 검증이 막힌다
원인 후보: 테스트 입력과 예상 결과가 없다.  
복구: 실제 고객 데이터가 없어도 가짜 입력 3개로 먼저 검증한다.

## 문제: 사람 승인이 계속 필요하다
원인 후보: 승인 자체가 목표가 되어버렸다.  
복구: 승인 전까지 자동으로 준비할 수 있는 부분을 분리한다. 사람은 발송/결제/계정/비밀/공개 같은 경계에서만 본다.
