# 03 Command Cards

## A. 자동화 설계 시작
```text
내 업무 자동화 설계자로 행동해라. 바로 만들지 말고 먼저 다음을 자연어로 정리해라:
목표, 입력, 출력, 사용하는 앱, 권한형 계정 연결, 사람이 확인할 경계, 자동화하면 안 되는 것, 성공 기준, 실패했을 때 복구 방법.
그 다음 첫 버전은 10분 안에 테스트할 수 있는 최소 흐름으로 제안해라.
```

## B. 껍데기 방지 명령
```text
지금 만든 결과가 겉보기만 있는 껍데기인지 검사해라.
실제 입력이 들어왔을 때 어디서 처리되고, 결과가 어디에 저장되고, 실패하면 누가 무엇을 봐야 하는지 설명해라.
비어 있는 부분이 있으면 "완료"라고 하지 말고 원인을 고쳐라.
```

## C. 플러그인/스킬 라우팅
```text
내가 하려는 작업에 필요한 플러그인/스킬/도구를 골라라.
각 도구마다 "무엇을 해주는지", "왜 필요한지", "대체 방법", "권한 연결이 필요한지", "라이브 실행 지시가 필요한지"를 쉬운 말로 적어라.
```

## D. 권한형 계정 자동화
```text
이 업무에 Gmail, Drive, Chrome, 커뮤니티, SNS, 대시보드 같은 계정 작업이 필요하면 우회하지 말고 권한형 자동화 구조를 설계해라.
연결 방식, 허용 라벨/검색어/URL/대상, 자동 실행할 읽기·분류·요약·초안·스테이징 작업, 라이브 발송/게시/제출 전 조건, 감사로그 위치를 표로 보여라.
비밀번호, 쿠키, 복구코드, 2FA 우회, 무제한 계정 읽기는 요구하지 마라.
```

## E. 결과 검증
```text
이 자동화 결과를 검증해라. 테스트 입력 3개를 만들고, 예상 결과와 실제 결과가 어떻게 달라지는지 표로 보여라.
실패한 경우 새 게이트를 추가하지 말고, 입력/프롬프트/도구/경로/권한 중 어떤 원인이 문제인지 고쳐라.
```

## F. 비전공자 설명
```text
이 결과를 코딩을 모르는 사람에게 설명하듯 다시 써라.
전문용어는 쓰되 바로 옆에 쉬운 설명을 붙여라.
내가 오늘 바로 해야 할 행동만 3개로 줄여라.
```
