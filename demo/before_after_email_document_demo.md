# Before / After Demo — Email & Document Automation

## 데모 목적
고객에게 이 팩이 단순 프롬프트 묶음이 아니라 "껍데기 자동화를 실제 흐름으로 바꾸는 운영표"라는 것을 보여준다.

## Before: 흔한 지시
```text
내 이메일 답장 자동화 만들어줘.
```

## Before 결과가 약한 이유
- 어떤 이메일인지 모른다.
- 답장 초안인지 실제 발송인지 모른다.
- Gmail, Docs, Sheets, Notion 중 어디에 남길지 모른다.
- 사람이 확인할 경계가 없다.
- 테스트 입력이 없다.
- 실패하면 무엇을 고칠지 없다.

## After: 운영팩 지시
```text
내 고객 이메일 처리 업무를 자동화 가능한 하나의 흐름으로 좁혀라.
바로 코딩하지 말고 먼저 입력, 반복주기, 판단 기준, 결과물, 저장 위치, 사람이 확인할 경계, 실패하면 큰 문제인 부분을 표로 채워라.
그 다음 정상 요청, 정보 부족 요청, 민감 요청 테스트 입력 3개를 만들고 예상 결과를 보여라.
마지막으로 실제 자동화는 첫 10분 테스트 버전만 제안해라.
```

## After 결과 예시
| 항목 | 내용 |
|---|---|
| 입력 | 고객 문의 이메일 |
| 판단 | 가격 문의 / 일정 문의 / 환불·불만 / 민감정보 |
| 출력 | 답장 초안 + 요청 분류 |
| 저장 | Gmail draft 또는 Google Docs |
| 사람 경계 | 발송 전 확인, 환불/불만/민감정보는 직접 처리 |
| 테스트 | 정상 문의, 정보 부족 문의, 민감정보 포함 문의 |
| 실패복구 | 분류가 틀리면 판단 기준을 수정, 초안이 길면 출력형식 수정 |

## 고객에게 보여줄 설명
전자는 AI에게 "무언가 만들어봐"라고 던진 것이다. 후자는 업무를 실제 자동화 가능한 구조로 바꾼 것이다. 차이는 코드 실력이 아니라 입력, 출력, 사람 경계, 테스트, 실패복구가 있느냐다.

## 스크린샷/영상 데모 구성
1. 왼쪽: Before 지시와 허술한 결과.
2. 오른쪽: After 지시와 표 형태 결과.
3. 마지막: `No-Shell Scorecard`로 After가 왜 통과인지 표시.
